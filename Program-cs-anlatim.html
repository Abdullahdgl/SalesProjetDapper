SalesPulse · M&Y Akademi Dapper Case

DataGenerator Program.cs — Satır Satır Anlatım

Bu belge ezber listesi değildir. Dosyanın neden yazıldığını, sıranın neden böyle olduğunu ve her bloğun SQL’e ne yaptığını anlatır.
Proje: SalesProjetDapper.DataGenerator · Hedef: boş tablolara sahte ama gerçekçi satış verisi basmak.

1. Bu dosya ne işe yarar?

Web sitesi değildir. Kullanıcı tıklamaz. Visual Studio’da DataGenerator’ı startup yapıp F5’e basınca açılan bir konsol programıdır. Görevi: appsettings.json’dan sayıları okumak, LocalDB’deki SalesPulse veritabanına bağlanmak, eski satırları silmek, Catalog listelerinden il / kategori / ürün / müşteri / sipariş üretmek, SqlBulkCopy ile SQL’e yüklemek, kapanmak.

Neden Web projesinin içinde değil? 40 bin (ileride 2 milyon) satır tarayıcı isteğiyle üretilmez. INSERT’i 40.000 kez Dapper ile döndürmek de yavaştır. Konsol + SqlBulkCopy “kamyonla yükleme”dir; satır satır kamyonet değildir.

Hoca JSON dosyasından hazır sipariş basmayı istemez. Dağılım C# içinde üretilir: İstanbul daha sık, Aralık daha yoğun, az müşteri çok sipariş.

Tek cümle: Program.cs, Catalog’daki gerçekçi dağılımı SQL tablolarına boşaltır. Web uygulaması sonra o tablolardan KPI ve grafik çeker.

2. Çalışma sırası (bunu bozma)

Foreign key vardır: sipariş, var olmayan müşteriye bağlanamaz. O yüzden doldurma sırası zorunludur:

  1. appsettings.json oku
  2. SQL bağlantısını aç
  3. Eski veriyi sil (FK’nin tersi sırada)
  4. Cities (81 il)
  5. Categories (30 kategori)
  6. Products (ürün kategori ister)
  7. Customers (müşteri şehir ister)
  8. Orders + OrderDetails + Payments birlikte

Tersine doldursan SQL “bu CityId / CustomerId yok” der.

3. using — hangi alet çantası

using System.Data;
using Microsoft.Data.SqlClient;
using Microsoft.Extensions.Configuration;
using SalesProjetDapper.DataGenerator;

Microsoft.Data.SqlClientSqlConnection ve SqlBulkCopy. SQL Server sürücüsü.
Microsoft.Extensions.Configurationappsettings.json okuma. Sayıları koda gömmemek için.

Kendi projenin adı alt çizgisizdir. Referans kopyada Sales_Projet_Dapper.DataGenerator yazar; sen using’i SalesProjetDapper.DataGenerator yapmazsan Catalog kırmızı yanar.

4. Ayarları okumak

var config = new ConfigurationBuilder()
    .SetBasePath(AppContext.BaseDirectory)
    .AddJsonFile("appsettings.json", optional: false)
    .Build();

AppContext.BaseDirectory exe’nin klasörüdür (bin\Debug\net8.0). JSON’un Properties’inde Copy to Output Directory = Copy if newer olmazsa dosya orada olmaz; program “file not found” veya ConnectionString missing der.

optional: false dosya yoksa sessizce boş geçmesin, hata versin diye.

var connectionString = config["ConnectionString"] ?? throw new InvalidOperationException("ConnectionString missing");
var customerCount = int.Parse(config["Customers"] ?? "100000");
var productCount = int.Parse(config["Products"] ?? "5000");
var orderCount = int.Parse(config["Orders"] ?? "2000000");
var batchSize = int.Parse(config["BatchSize"] ?? "50000");

?? anlamı: JSON’da yoksa sağdaki yedek (veya throw). Geliştirmede 40.000 sipariş, teslimde 2.000.000 için sadece JSON değişir; C#’a dokunmazsın. Web projesindeki key SqlConnection (ConnectionStrings altında) ile karıştırma. Generator’da kökte ConnectionString vardır.

Konsola hedef yazılır ki F5’te “acaba çalıştı mı?” diye tahmin etmeyesin.

5. Bağlantı, ağırlıklar, zar

await using var connection = new SqlConnection(connectionString);
await connection.OpenAsync();

Kapı açılır. await using iş bitince bağlantıyı kapatır. Open olmadan BulkCopy yazamaz.

var cityWeights = Catalog.Cities.Select(c => c.Weight).ToArray();
var rng = new Random(2026);

cityWeights: İstanbul 180, küçük il 2. WeightedIndex bu diziyle “adil olmayan kura” çeker. Büyük şehir daha sık çıkar; gerçek e-ticaret gibi.

Random(2026): 2026 tohumdur. Aynı tohum ≈ aynı sahte dünya. Her F5’te tamamen başka müşteri/sipariş olmasın diye. Sunumda “neden her seferinde top müşteri değişti?” sorulmasın.

6. Ana çağrı sırası

await TruncateAsync(connection);
await BulkCitiesAsync(connection);
await BulkCategoriesAsync(connection);
await BulkProductsAsync(connection, productCount, rng);
await BulkCustomersAsync(connection, customerCount, cityWeights, rng);
await BulkOrdersAsync(connection, orderCount, customerCount, productCount, cityWeights, batchSize, rng);

Her await bir önceki bitmeden sonrakine geçmez. Ürünü müşteriden önce basmak gerekir; sipariş ikisini de ister.

En sonda konsol “Tamamlandı, indeks ve SP çalıştırın” der. İndeks henüz yoksa (Adım 5) bulk daha hızlıdır. Önce veri, sonra indeks — bilinçli sıra.

7. TruncateAsync — silme

İsim Truncate ama komut DELETE’tir. FK’li tabloda TRUNCATE çoğu zaman izin vermez.

Silme sırası doldurmanın tersidir: önce Payments, OrderDetails, Orders, Customers, Products, Categories, en sonda Cities. Çocuk varken baba silinmez.

CommandTimeout = 0: süre sınırı yok. 2 milyon satırda 30 saniyede kesilmesin.

Sonuç: her F5 tabloları sıfırlar, üstüne eklemez. SSMS’te 40.000 görüp script’i veya generator’ı tekrar çalıştırırsan tekrar 0’dan başlar.

8. BulkAsync — asıl yükleyici

Diğer Bulk* metodları DataTable doldurur; SQL’e basan tek yer burasıdır.

using var bulk = new SqlBulkCopy(connection,
    keepIdentity ? SqlBulkCopyOptions.KeepIdentity : SqlBulkCopyOptions.Default, null);
bulk.DestinationTableName = tableName;
bulk.BulkCopyTimeout = 0;
// kolon adı = SQL kolon adı
await bulk.WriteToServerAsync(table);
KavramAnlamı
DataTableRAM’de satırlar. Henüz SQL değil.
SqlBulkCopyKovayı SQL tablosuna tek seferde (veya büyük parçalarla) döker. 40.000 INSERT’ten hızlıdır.
KeepIdentity trueSenin CityId=1,2,3 değerlerin kalsın. SQL IDENTITY’yi kendisi 5’ten başlatmasın. Siparişte CityId=1 yazıyorsan 1 gerçekten İstanbul olmalı.
KeepIdentity falseOrderDetails ve Payments. Satır Id’sini SQL versin. Senin bağladığın OrderId yeter.
ColumnMappingsDataTable “Name” ↔ SQL “Name”. İsim şemayla aynı olmazsa kolon boş veya hata.

9. BulkCitiesAsync / BulkCategoriesAsync

Catalog.Cities ve Catalog.Categories üzerinde döner. i=0 iken Id=1 (SQL 1’den başlar). İsim ve bölge listeden gelir. KeepIdentity true.

JSON yok. 81 il ve 30 kategori kodda sabittir; generator her çalıştığında aynı iller, aynı Id’ler.

10. BulkProductsAsync

var categoryId = ((i - 1) % Catalog.Categories.Length) + 1;

% kalan operatörüdür. 30 kategori varsa 1. ürün kat 1, 31. ürün yine kat 1. Ürünler kategorilere eşit dağılır; tek kategoride 5000 ürün olmaz.

Fiyat: 19.90 ile yaklaşık 4819.90 arası rastgele, 2 ondalık.

IsActive: NextDouble() > 0.04 → kabaca %96 aktif, %4 pasif. Gerçek katalogda her SKU satışta değildir.

İsim örneği: "Elektronik #0001". Uydurma ama kategori adını taşır; raporlarda okunur.

11. BulkCustomersAsync

25.000 satırı tek seferde RAM’de tutmak yerine 20.000’lik dilimler: doldur → BulkAsync → Clear → devam. Bellek şişmesin, konsolda “Customers: 20000” diye ilerleme gör.

  • Ad ve soyad Catalog dizilerinden rastgele. Aynı isim tekrarı normal (sahte veri).
  • E-posta user{i}@mail.salespulse.local — şemada email unique; i benzersiz olduğu için çakışmaz.
  • CityId = WeightedIndex(cityWeights, rng) + 1 — İstanbul daha sık.
  • RegisteredAt: 2021-01-01’den itibaren rastgele gün. Sipariş tarihi 2023’ten başlar; kayıt siparişten önce durur, mantıklı geçmiş.

12. BulkOrdersAsync — asıl zekâ

Üç DataTable: orders, details, payments. Sipariş başlığı, kalemler, tahsilat. 10.000’de bir (batchSize) üçü birlikte basılır. Siparişi basıp kalemi yarına bırakırsan FK kırılır.

12.1 Hangi müşteri? (Zipf benzeri)

customerId = 1 + (int)(Math.Pow(rng.NextDouble(), 2.15) * (customerCount - 1));

NextDouble() 0 ile 1 arası. Üssü 2.15 alınca sonuç çoğu zaman küçük kalır. Id’ler 1, 2, 3 civarına yığılır: az müşteri çok sipariş. Düz rng.Next(1, customerCount) olsa herkes eşit; “en yüksek ciro 20 müşteri” grafiği anlamsız olurdu. Ürün seçimi aynı fikir, üs 1.8: az ürün çok satılır.

12.2 Hangi gün? WeightedDay

2023-01-01 ile bugün arasında rastgele bir gün (saat 8–23) üretir. O ayın MonthWeight değerine bakar. Aralık 160, Ocak 70. Zar: 0–169 arası sayı ağırlıktan küçükse tarihi kabul eder, değilse başka gün dener. Kasım–Aralık zirvesi böyle çıkar. MonthWeight[0] yanlışlıkla 0 kalırsa Ocak neredeyse hiç kabul edilmez.

12.3 Durum ve ödeme

Catalog.Statuses içinde Completed yedi kez yazılıdır → çoğunluk tamamlanmış sipariş. Payments içinde CreditCard üç kez → kart baskın. Dizide tekrar, if-else kalabalığından basit bir ağırlıktır.

12.4 Kalemler

%55 ihtimal tek kalem, değilse 2–4 kalem. LineTotal = birim fiyat × adet. TotalAmount C#’ta kalemlerden toplanır. Header tutarı ile detay toplamı çelişmesin diye SQL’e ayrı ayrı uydurulmaz.

12.5 Payments

Sipariş başına bir satır (şemada OrderId unique). Cancelled veya Pending ise PaidAt boş (DBNull): tahsilat olmamış. Cancelled → Failed, Pending → Pending, diğerleri → Paid. İptalde para alınmış gibi durmasın.

12.6 OrderNumber

SP + 10 haneli numara (SP0000000001). Unique kısıt var; i tekil olduğu için çakışmaz. Ekranda kullanıcıya gösterilen sipariş no budur, ham OrderId değil.

13. WeightedIndex — ağırlıklı kura

Ağırlıkları topla (örnek 1500). 0 ile 1499 arası zar at. Birikimli aralık: 0–179 İstanbul, sonraki 80 Ankara… Büyük ağırlık = daha geniş aralık = daha sık seçilme. 81 ile eşit rng.Next(81) kullanırsan İstanbul ile Bayburt aynı sıklıkta çıkar; bölgesel ciro grafiği yalan olur. +1 çünkü dizi 0’dan, SQL Id 1’den başlar.

14. Bu kodun hocanın ödevindeki yeri

  • Hacim: raporlar boş tabloda anlamsız; GROUP BY / HAVING için binlerce satır gerekir.
  • Gerçekçilik: eşit rastgele veri “İstanbul 1. sırada” üretmez; ağırlık ve Zipf bunun için.
  • Performans hikâyesi: önce bulk, sonra indeks. Generator indeks yokken daha hızlı dolar.
  • Web’den ayrılık: panel 2 milyon satır üretmez, sadece okur.

15. F5 sonrası ne görmelisin?

Konsol: Cities 81, Categories 30, Products 5.000, Customers 25.000, Orders 40.000.

SSMS:

USE SalesPulse;
SELECT COUNT(*) FROM dbo.Cities;      -- 81
SELECT COUNT(*) FROM dbo.Customers;   -- 25000

Hâlâ 0 ise ya hâlâ Hello World Program.cs çalışıyordur, ya startup proje Web’dir, ya bağlantı başka sunucuyadır.

16. Okuma haritası (ezberleme)

  1. JSON = kaç satır ve nereye bağlanacağım.
  2. Truncate = FK tersi silme, her çalıştırmada temiz sayfa.
  3. Bulk* = DataTable doldur.
  4. BulkAsync = kamyon (SqlBulkCopy), KeepIdentity Id’leri senin verdiğin gibi tutar.
  5. WeightedIndex / WeightedDay / pow = gerçekçi çarpıklık, eşit zar değil.
  6. Sipariş + kalem + ödeme aynı batch’te = ilişki kopmasın.
